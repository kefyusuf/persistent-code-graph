# M1.5 — Parser → Persistent Store → Incremental Refresh → Verified Query

**Date:** 2026-11-01  
**Project:** Persistent Code Graph  
**Decision:** **PROVISIONAL / BLOCKED** for real grammar acceptance. Independent offline integration slice verified; production and M1.3 acceptance denied.  
**Scope:** no new language support, MCP, graph resolver, agent memory, cloud, Git hooks, or daemon.

## 1. Problem and choice

Previous spikes proved independent properties but had not tied a real grammar
provider to the immutable store and verified query lifecycle. M1.3 remained
blocked because npm DNS access prevented installing pinned grammars. Advancing
other features while implicitly treating the M1.2 temporary parser as a
production substitute would create false confidence.

**Decision:** use one small explicit pipeline whose source parser provider must
state provenance. The real provider obtains its identity from the actual WASM
grammar SHA-256 and does not fall back if a package is missing. The independent
offline test provider is clearly identified as experimental.

## 2. Runtime composition

```text
Git checkout (bytes on disk)
  -> Git-aware source inventory (SHA-256 per eligible file)
  -> parser identity from installed grammar SHA-256
  -> reuse unchanged immutable file-fact objects / extract changed files
  -> compare source inventory before publication
  -> atomically publish a new checkout snapshot head
  -> verified read-only query (double content hash scan)
  -> bounded declarations / references / outline / status
```

Two entry points:

- `createFileFactsPipeline({checkoutRoot,indexRoot,provider})`: explicit, testable
  provider boundary; `provider.provenance` is required.
- `createRealTreeSitterPipeline({checkoutRoot,indexRoot})`: only the real provider,
  prepared before refresh by loading every grammar needed by eligible files.

All query responses carry `parserProvenance` and `semanticGraph: false`.
`verified` is strictly point-in-time source freshness. No reference target is
silently inferred or promoted to a call edge.

### Offline integration assertions

1. First index of actual PHP and TS files creates two persisted records.
2. New pipeline instance and separate Node.js process can reopen/query them.
3. No-op refresh makes **zero extractor calls**; active snapshot unchanged.
4. One PHP edit produces `stale`, zero old facts, then reparses only that file.
5. After that edit, a cold index and a warm index have identical saved facts.
6. Parser identity drift causes reparse even when source content is unchanged.
7. File deletion removes stale file facts; query still makes limited claims.
8. Failed extraction or mid-refresh source mutation preserves the previous head.
9. Malformed-source coverage is not falsely promoted to complete.
10. Queries do not call the parser and preserve output limits.
11. Provider provenance is required; callers cannot override query parser identity.

### Illustrative benchmark — synthetic local files, not generalizable

- 80 tiny PHP files using the **M1.2 temporary tokenizer**, not Tree-sitter.
- Cold refresh: 1560 ms; warm refresh: 125.21 ms; warm parser calls: 0.
- Five individual exact symbol queries: 113.73, 113.44, 77.04, 99.90, 59.52 ms.
- Environment-dependent, uncalibrated single run. Query cost is still O(N)
  full-file rehashing twice, plus persisted snapshot reads. Token costs and
  accuracy were **not** measured. See `spikes/m1.5/reports/BENCHMARK-80-FILES.json`.

## 4. Known limitations and risk acceptance

- **Parser:** real grammar integration is not approved; an offline 101/101 pass
  does not say PHP/TS/TSX are fully supported.
- **Semantics:** graph *store* still contains file-level syntax facts, not a
  semantic call graph. `relations` are empty until a separate resolver is built.
- **Performance:** every query reads/hashes all eligible source files twice,
  which can be excessive for a large repository. A faster verification policy
  requires explicit threat/consistency assumptions and benchmarks first.
- **Atomicity:** source files can change after the final verification. Head
  publication itself is atomic, not a transaction over the entire source tree.
- **Concurrency:** orphaned locks fail closed, with no automated recovery.
- **Portability:** Linux tests only; Windows, symlinks, pathological filename
  encodings, large repositories, and abrupt power loss remain unverified.
- **No magic completeness:** a verified empty result means "not observed in the
  indexed subset", never "the symbol cannot exist".

## 5. Acceptance criteria for M1.5

The milestone must remain blocked until:

1. Locked/verified dependencies install reproducibly and all 12 M1.3 real
   grammar fixtures pass (PHP, TS, TSX; malformed source and unicode included).
2. All 3 M1.5 unskipped real-provider end-to-end tests pass: cold indexing,
   warm zero parse, process restart, changed-file refresh and verified query.
3. Any differences between experimental and real AST extraction are reviewed,
   with no untruthful relation or completeness claims.
4. One actual repository's runtime and cache growth are measured. Offline
   estimates are not treated as guarantees of token savings.
5. Prior 101 offline tests continue to pass unchanged.

**Next action:** run M1.3/M1.5 real grammar gates on a machine with package
registry access, diagnose any AST discrepancies, then decide whether to accept
M1.5. Do not expand to MCP, hooks, dashboards, or additional languages first.

## 6. Architectural self-review

- **Scope:** preserved — one small integration adapter and reproducible tests.
- **Evidence:** clearly separates temporary offline feasibility from unverified
  real grammar behavior; real tests fail instead of being skipped.
- **Determinism:** actual grammar and extraction implementation bytes determine cache identity in the real
  provider. Unchanged source may reuse immutable objects, not reparse.
- **Correctness:** failed extraction blocks publication and reads cannot
  silently treat changed code as current.
- **Open concern:** read-time double hashing is currently costly and can grow
  linearly. This needs explicit measurement before automatic agent integration.
- **No repository mutation:** no commit, PR, AI attribution, skill, or hook written.
