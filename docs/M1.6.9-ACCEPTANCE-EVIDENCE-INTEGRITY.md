# M1.6.9 — Acceptance Evidence Integrity

**Status:** Tested locally; GitHub CI required before integration.  
**Scope:** Acceptance status evaluation only. No parser, storage, query, snapshot, or public API changes.

## Problem and evidence

The baseline `acceptanceStatus(mode, results)` previously counted reported groups without validating their identities or positive test counts. Consequently, a duplicate group replacing `m1.6-real-grammar` could yield `PASS`, as could a result set where every reported group had zero tests. These are reproducible defects in the *gate evaluator*, not evidence that previous CI runs were fabricated. Historical CI logs show real test execution.

## Minimal repair

- Validate that results contain exactly the IDs required by `gatePlan(mode)`, with no missing, duplicate, or unknown IDs.
- Require each successful group to report strictly positive integer test counts and `pass === tests`.
- Preserve `FAIL` for explicit failed/skipped/cancelled test evidence; return `BLOCKED` for absent or inconsistent positive evidence.
- Keep `OFFLINE_ONLY` distinct from real-parser `PASS`.

No new runtime dependencies or infrastructure are introduced. The runner continues to enumerate and execute its registered suites in the same order.

## RED → GREEN evidence

Four new tests were added to `tools/tests/gate.test.mjs`:

1. Repeated offline suite cannot substitute for a real-grammar suite.
2. Unknown gate cannot stand in for a required suite.
3. Empty or internally inconsistent success counts cannot produce `PASS`.
4. The same identity checks also apply in `offline` mode.

RED: 6/10 tests passed; four new tests failed, as expected.  
GREEN: 10/10 gate tests passed.  
Regression: `node tools/verify-gates.mjs --mode offline --output reports/m1.6.9/offline.json` returned `OFFLINE_ONLY` with **161/161 passed**, zero failed and zero skipped.

Full Tree-sitter suite **must run on GitHub Actions for the exact PR head** before any claim of full acceptance. Current local results do not assert parser acceptance.

## Remaining limitations

The evaluator trusts that the invoked Node test runner is correctly enumerating the declared test files. It does not cryptographically attest test binaries, npm artifacts or runner execution. Existing signed-package, supply-chain and hostile-runner verification is outside scope.

The source index itself remains an experimental, partial, syntax-only file-facts index rather than a complete resolved semantic code graph.
