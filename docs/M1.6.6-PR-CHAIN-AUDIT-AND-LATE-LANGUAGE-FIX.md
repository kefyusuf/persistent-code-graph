# M1.6.6 — PR-chain audit and late-language refresh regression

## Scope

This is a correctness repair found while reviewing stacked Draft PRs #1–#7. It does not add language support, change the on-disk schema, implement semantic resolution, introduce an agent service, or merge any branch to `main`.

## Baseline review

- The seven PRs are stacked sequentially, from M1.5.2 to M1.6.5; all seven were open and Draft at review time.
- Each PR's latest commit had a completed successful GitHub Actions run. The latest pre-fix head was `a689b8df62b2fc68fdd5ee11436a7c4be2c2c855` (PR #7).
- Local reproduction of the existing offline gate was **151/151 passed**. This is offline evidence only.
- No PR was merged, and absence of merge conflicts or green CI is not a production-readiness determination.

## Finding LATE-LANG-001 (correctness regression)

`prepareTreeSitterProvider(checkoutRoot)` initializes a synchronous parser-identity map for the languages present *when the pipeline opens*. An explicit later `refresh()` can see a newly added supported-language file (e.g. a `.ts` file in a previously PHP-only checkout) that was never registered and throw `UNPREPARED_LANGUAGE`.

Impact: explicit incremental refresh fails for an ordinary supported new file; `openCodeGraph` must be recreated to recover. This contradicts the intended incremental refresh contract.

### RED reproduction

A new offline test passes a provider whose identity function fails unless `prepareLanguages()` has registered the current inventory languages. Before the repair, `node --test test/core.test.mjs` produced one failure with `UNPREPARED_LANGUAGE`.

### Minimal repair

1. During `refreshFileFacts`, after its existing first inventory scan and before checking cache identities, optionally call a provider-supplied asynchronous `prepareForLanguages(languages)` callback.
2. Forward the optional `prepareLanguages()` provider capability from the existing pipeline; retain compatibility with providers that do not need preparation.
3. Register missing supported grammars on the real provider without changing already registered identities. Continue loading grammar files from the pinned root dependencies.
4. Keep inventory scanning count unchanged. No new watcher, background job, parser fallback, resolver, data schema, or network request.

### Acceptance evidence

- Offline regression: new supported language added after first refresh and initial empty checkout becoming nonempty; source and snapshot freshness remain verifiable. **153/153 offline tests passed** locally after repair.
- CI-only regression: real PHP → new TypeScript and TSX files added without reopening the pipeline. It requires actual pinned WASM grammar assets and must pass on the final GitHub head before accepting this fix.
- All previous gates must remain green. No skipping of grammar tests is permitted.

## Residual risks and decision

- The source double-hash verification is point-in-time only. File-system races after the final verification remain an explicitly documented limitation.
- Symlink handling, writer-lock recovery, cross-platform crash safety and full semantic resolution require separate gates; do not equate this repair or any green CI run with production readiness.
- **Merge decision: HOLD** until the new CI gate passes and stacked PRs have been reviewed/integrated in order. `main` is intentionally untouched.
