# M1.6.1 — Canonical Parser Module Migration

Status: **implementation candidate; awaiting full GitHub Actions gate**.

## Intent

Move the tested M1.3 Tree-sitter grammar runtime and extraction contract, and the M1.5 real-grammar provider, into a canonical parser directory without introducing language features, a new storage engine, a new package manager, or a new service.

## Canonical ownership

- `src/parser/contract.mjs`: language classification, syntax fact extraction, normalization, offset/diagnostic handling, and parser cache identity.
- `src/parser/runtime.mjs`: pinned WASM grammar loading and hashing, Tree-sitter extraction, source-code hash provenance.
- `src/parser/provider.mjs`: immutable provider, inventory-based preparation, parser identity consistency checking.
- `src/core.mjs`: now imports the canonical provider.

Existing experiment entrypoints in `spikes/m1.3/src/{contract,runtime}.mjs` and `spikes/m1.5/src/tree-sitter-provider.mjs` are **re-export-only** compatibility shims. They must not become independent implementations.

## Dependency and cache decisions

The pinned dependencies `web-tree-sitter@0.27.1` and `tree-sitter-wasm@2.0.4`, their lockfile, and CI installation location remain under `spikes/m1.3` in this migration. The new runtime resolves dependency modules **relative to that exact manifest**, not the process working directory. Package consolidation is explicitly deferred.

The extractor stamp is computed from the bytes of the **canonical** `contract.mjs` and `runtime.mjs`. This changes the parser cache identity compared to the M1.6 implementation; existing file facts must be re-parsed once and must never be treated as compatible based only on the grammar version. The grammar binary hash remains part of the cache identity.

There is no fallback to the temporary PHP tokenizer or the TypeScript compiler parser in the public entrypoint. Syntax observations remain **partial** and do not fabricate cross-file semantic relations.

## Acceptance and evidence

1. RED: the new parser migration tests initially fail because the canonical modules do not exist.
2. GREEN: all historical import paths refer to the same canonical exported functions, language detection and cache identities behave as before, and core imports the canonical provider.
3. Full validation: all existing M1.2–M1.6 tests plus the new M1.6.1 suite, **and** all real grammar tests, must pass in CI after installing pinned dependencies.
4. Branch/PR only; no merge before full gates pass.

## Explicitly deferred

Moving the M1.4.x persistent store and query modules out of `spikes/`, removing compatibility shims, changing the repository package lockfile structure, CLI/MCP integration, watcher support, additional languages, and cross-file semantic resolution.
