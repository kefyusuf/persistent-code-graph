## Defect — storage path with a symlinked ancestor

### Failure mode

`CodeGraphStore` previously stored `resolve(indexRoot)` (lexical normalization) and checked that path against the physical `realpathSync(checkoutRoot)`. An outside-looking `indexRoot` such as `/tmp/external-alias/.cache` could still write *inside* the checkout when `/tmp/external-alias` was a symlink to `/tmp/checkout`. This conflicts with the source-write boundary.

### RED evidence

Four regression scenarios were authored. The two unsafe checkout symlink cases failed against the prior implementation, and the safe outside-link case passed. The dangling-symlink case was added to fail closed on an indeterminate destination.

### GREEN implementation

`CodeGraphStore` now resolves the nearest **existing** filesystem ancestor of the index root with `realpathSync`, appends any not-yet-created child components, and rejects a resulting path at or inside the checkout. A broken symlink is rejected rather than treated as an absent directory. Successful paths are stored in their physically resolved form, removing reliance on later traversal through the original symlink alias.

No snapshot schema, object identity, parser identity, file-facts format, query semantics, or Git inventory logic changed.

## Explicit limits and deferred risks

- Canonicalizing `indexRoot` during store construction prevents the observed preexisting alias, but does not establish a general defense against adversarial filesystem mutation *after* construction (e.g., replacement of index subdirectories by another process). A hardened, race-resistant directory-handle policy remains out of this milestone.
- Crash durability and orphan-lock recovery on Windows remain unverified.
- File-fact coverage is partial, not a resolved cross-file semantic graph.
- No token-efficiency or large-project latency claims are inferred from these tests.
