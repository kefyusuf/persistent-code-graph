# M1.6.5 — Standalone Runtime Dependency Boundary

Status: **CI verified on implementation commit `d2519292`**; the release remains experimental and the stacked PR is still Draft.

## Problem

After the M1.6.1–M1.6.4 code moves, the canonical parser runtime still resolved its production packages from `spikes/m1.3/package.json` and `spikes/m1.3/node_modules`. A package installed without historical spike sources therefore could not load real grammars. Code ownership under `src/` alone was not sufficient isolation.

## Decision

- Use root `package.json` and committed root `package-lock.json` for exact `web-tree-sitter@0.27.1` and `tree-sitter-wasm@2.0.4`, including published integrity hashes.
- Resolve modules and manifests relative to the root package, independent of process working directory. No runtime fallback to any experimental parser or the old spike installation.
- Preserve the existing M1.3 package and lockfile to run historical grammar tests independently. They do not provide dependencies to the canonical runtime.
- Keep source hashing of `src/parser/runtime.mjs` and `src/parser/contract.mjs` within the parser cache identity. The changed runtime module will invalidate older cached facts on refresh; on-disk snapshot schema is unchanged.
- Add the root lockfile to the GitHub Actions reproducibility condition and install root dependencies using `npm ci`.

## Scope and risks

This is package-boundary consolidation only. It is **not** a published package release, semantic graph resolver, Windows crash durability claim, concurrency guarantee, or proof of token savings. The real test copies pinned dependencies to simulate a spike-free installation; publishing and Windows platform testing remain separate gates.

No changes to query semantics, refresh inventory, source authority, index schema, stable symbol IDs, or candidate language list. No MCP, agent memory, RAG, UI, cloud, or background indexing.
