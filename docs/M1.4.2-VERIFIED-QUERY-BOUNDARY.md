# M1.4.2 — Verified Read-Only Query Boundary

**Project:** Persistent Code Graph  
**Date:** 2026-11-01  
**Decision:** ACCEPT as a **parser-neutral local feasibility spike** (26/26 tests). **DO NOT ACCEPT** M1.3 real grammar compatibility or the production graph/indexer.  
**Milestone scope:** one read-only query module over M1.4 immutable snapshots and M1.4.1 Git inventory. No new service or runtime dependency.

## 1. Problem

A durable index can be outdated a moment after it is written. A coding agent must not silently treat source symbols and call observations as current just because the index can be reopened. Queries must also avoid returning arbitrary amounts of content to an LLM.

**Decision:** provide narrow, bounded queries only after point-in-time file-content and parser-identity checks; fail closed on detected drift, uncheckable sources, corrupt snapshots, or concurrent head replacement. A second complete verification scan is performed before returning results. This is not a guarantee of continuous freshness.

## 2. Implementation

- Source: `spikes/m1.4.2/src/query.mjs`.
- Input: `checkoutRoot`, `indexRoot`, **required** `parserIdentity(language)`, query operation and optional selectors.
- Dependencies: existing `CodeGraphStore` and `inventoryGitCheckout`. No additional npm dependencies.
- Supported operations: `status`, `declarations`, `references`, `outline` (file-specific declaration list).
- Selectors are exact: `name`, `kind`, `role`, `spelling`, `file`. No fuzzy matching, inferred call target, semantic ranking, or source-code snippets.
- Response fields: `state`, `snapshotId`, `results`, `coverage`, `noMatchMeans`, `truncated`, and `verification` on positive reads. Drift summaries are returned on a stale response; uncheckable inventory reports a bounded `reasonCode`.
- Limits: default 12 records, maximum 25. Result-list JSON size defaults to 4 KiB and is capped at 16 KiB (`maxBytes`); this is a **result-list budget**, not a strict whole-response token budget. Drift paths are capped at 25 per category with full category counts retained.
- Stored reference observations have `resolutionStatus: unresolved`; neither a parsed call spelling nor a matching method name is proof of a call edge.

### Query transition

```text
Read/verify immutable snapshot
    -> Git inventory scan #1 (read bytes, verify UTF-8, calculate SHA-256)
    -> compare file set, language, content hash, and parser identity
        -> changed: STALE + no source facts
        -> cannot verify: UNKNOWN + no source facts
        -> matches: produce ordered, bounded facts in memory
    -> Git inventory scan #2; check active snapshot head again
        -> mismatch/head change: STALE + no source facts
        -> cannot verify: UNKNOWN + no source facts
        -> matches: VERIFIED (point-in-time only)
```

`verified` asserts that the two scans and head check matched **during this invocation**. Source changes may occur immediately afterward. The consumer must recheck on its next independent query and must not represent `verified` as an enduring property of the repository.

### Response states

| State | Meaning | Facts returned? |
|---|---|---|
| `missing` | No active index exists | No |
| `stale` | Source files, parser identities, or active snapshot diverged | No |
| `unknown` | Git inventory or source encoding cannot be checked reliably | No |
| `verified` | Both scans, persisted head and parser identity matched at verification time | Yes, bounded |

Any immutable object/snapshot integrity failure is raised as `INTEGRITY_ERROR`, never converted into a plausible empty search.

`coverage` is conservative: `failed` if the stored facts include failed coverage, `not-evaluated` if some are unassessed, otherwise `partial`. Zero results always means `not-observed-in-indexed-subset`, **not** "the symbol does not exist".

## 5. Architectural self-review

- **Preserved:** source-of-truth principle, offline/deterministic operation, parser-independent interface, read-only query boundary, no new service/database, no MCP/LLM/memory.
- **Correctness:** actual Git working-tree bytes are hashed; staged and committed metadata are not mistaken for working-tree content. A second scan blocks observed in-flight changes. Parser identity is required, not inferred from the old index.
- **Known limitation (TOCTOU):** there is still a race after final verification. No cross-file atomic filesystem snapshot is taken. Callers must describe freshness as point-in-time only.
- **Known limitation (performance):** each query reads and hashes every eligible source file twice and rereads the persisted snapshot. This may defeat latency targets on large repositories; optimize only after profiling and without claiming stronger assurance than measured.
- **Known limitation (semantics):** references are observations, not verified cross-file relations. No call graph, reverse call lookup, impact analysis, or general purpose agent code understanding yet.
- **Known limitation (coverage):** only the small partial PHP/TS temporary extractor is exercised; unsupported syntax can be missed. TSX and all other languages are not validated here.
- **Known limitation (platform):** the package was verified on Linux; Windows path semantics, external Git worktree races, power-loss durability and lock recovery remain unverified.
- **Known limitation (resource use):** output bounds are result-list bounds; the total response and repeated source scans still have costs. Exact file selectors do not guarantee index completeness.
- **Security:** integrity errors fail closed. This is a local prototype and is not hardened as an untrusted multi-tenant service.

## 6. Decision and next gate

**M1.4.2 feasibility ACCEPTED.** It proves a read-only, bounded and point-in-time verified query interface can sit above the existing experimental store and Git inventory without adding a new subsystem.

**Not accepted:** M1.3 Tree-sitter grammar integration, full M1.5 parser-to-store product integration, production-ready index, semantic relation graph, token savings, multi-language production support, or performance suitability.

Next gate:

1. Complete actual M1.3 grammar integration and make the 12 real-parser tests pass on a pinned, reproducible install.
2. Add a whole-flow M1.5 test using accepted parser facts: first index → persisted reload in a new process → unchanged warm index zero parser calls → change only one file → cold vs warm graph/relationship equivalence → verified query.
3. Measure source scan and response overhead before adopting an automatic query-before-read policy for agents.
4. Keep MCP, hooks, background jobs, cloud, UI, embeddings and AI memory out of scope until the core is accepted.

No GitHub repository, branch, commit, PR, user agent configuration, installed skill, or hook was changed by this local spike.
