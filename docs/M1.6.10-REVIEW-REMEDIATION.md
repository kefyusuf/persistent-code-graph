## Findings verified from PR #1 CodeRabbit review

The automatic review of PR #1 returned 16 findings. We independently inspected the concrete runtime paths against the latest PR #10 head, rather than treating historical prototype code as the final implementation.

1. `spikes/m1.5/src/pipeline.mjs`: the bound single-query pipeline accepts arbitrary selector keys that override `checkoutRoot`, `indexRoot`, or insert a test seam. This still exists in the canonical `src/core.mjs` at PR #10. **Valid, fixed here.** Only `name`, `kind`, `role`, `file`, `spelling`, `limit`, and `maxBytes` are accepted for single-query selectors. Batch request constraints are unchanged.
2. `tools/verify-gates.mjs`: lexical report path validation permits a symlink in `reports/` that targets another directory. A caller can also choose a source file as `--output`. **Valid, fixed here.** Reports must be written beneath `reports/`; any existing symlink component or symlinked output is rejected before any test or write. The report writer remains an explicit CLI action; this is a static, fail-closed path check, not a concurrent adversarial filesystem defense.
3. `spikes/m1.5/tests/pipeline.test.mjs`: `q.coverage.declarations` always evaluates to `undefined` because the query returns a string coverage summary. **Valid, fixed here** to assert the actual `failed` state for malformed input.
