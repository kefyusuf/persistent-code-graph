# M1.6.12 — Indexed Source Span Extraction

**Scope:** Active Tree-sitter file-fact source positions only; [Issue #12](https://github.com/kefyusuf/persistent-code-graph/issues/12).
**Base:** M1.6.11 documentation PR #13. No parser grammar, storage, query, snapshot format, CLI, MCP, or semantic resolution changes.

## Root cause and bounded repair

Before this change, each declaration, reference and diagnostic called `spanForNode(source, node)`, which copied the entire source buffer and rescanned its prefix for newlines. Repeated occurrences therefore incurred repeated O(file bytes) work.

`createIndexedSpanResolver(source)` now constructs a UTF-8 source buffer, a UTF-16-to-UTF-8 offset map, and newline-start indices once per `fileFactsFromTree` invocation. The resolver first checks byte-index coordinates, then UTF-16 coordinates, and requires exact `node.text` equality; uncertain offsets still fail closed with `OFFSET_INCONSISTENCY`. It preserves half-open 0-based byte ranges, 1-based lines, CRLF, astral Unicode and zero-width diagnostics. The existing `spanForNode(source,node)` helper remains available as a compatibility wrapper.

Runtime cache identity already contains a SHA-256 stamp of the extractor source (`contract.mjs` and `runtime.mjs`), so the changed contract invalidates prior extracted-fact cache identities. No persisted schema or external API has changed.

## RED → GREEN / regression

- Three new offline span contract tests initially failed because the indexed resolver was missing: 13/16 passed (RED). After implementation all 16 passed (GREEN).
- Coverage: byte vs JS coordinates, repeated source text, CRLF, astral Unicode, zero-width spans and mismatch failure.
- Two added actual-WASM grammar cases check PHP, TS and TSX source positions and 160 repeated TypeScript calls; full CI is the acceptance authority.
- A separate local differential check compared complete file-fact outputs with the pre-change implementation for 55 synthetic TypeScript and TSX call occurrences and found no differences.
- Local offline suite in a prior working copy: 167/167, OFFLINE_ONLY; this checkout does not contain all of PR #13's latest test files. Do not interpret this figure as the final stacked-branch count.

## Reproducible synthetic measurement

Run `node tools/benchmarks/span-extraction.mjs` from the repository root.

Linux, Node.js v22.16.0. One warmup and five samples per revision, with identical script and input: 235,816 UTF-8 source bytes, 900 synthetic TypeScript call occurrences and an astral Unicode prefix. This measures extraction from an already constructed synthetic syntax tree; it does not measure real WASM parse, Git scan, source hashing or persistence.

| Revision | Five runs (ms) | Median (ms) |
|---|---|---:|
| Original | 1012.67, 1032.78, 1061.25, 1064.19, 1107.82 | 1061.25 |
| Indexed | 4.50, 6.58, 7.91, 9.65, 9.85 | 7.91 |

The median difference is approximately 134× **in this synthetic microbenchmark only**. No claim of production speedup, repository-wide latency reduction or token savings is made. The indexed map uses memory linear in UTF-16 source length; representative large-repository memory and timing remain unverified.
